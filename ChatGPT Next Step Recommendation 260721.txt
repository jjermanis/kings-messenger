First, congratulations on getting to this point. I think you've crossed an important milestone.

Originally, King's Messenger was essentially a hard-coded demo. Today it's become a game engine:

✓ Level geometry comes from JSON.
✓ Player start comes from JSON.
✓ Enemy placement comes from JSON.
✓ Levels can be created with a visual editor.
✓ The editor and the game now speak the same file format.

That's a substantial architectural improvement.

My recommendation

If this were a commercial project, I'd recommend a period of stabilization before adding lots of new features. Not because the game isn't fun to extend, but because you're at a point where future features become much easier if the foundation is solid.

Here's how I'd prioritize the next work.

Tier 1 — Stabilize (my first choice)

These are all relatively small tasks with a high payoff.

Replace the remaining hard-coded constants with level data where appropriate.
Verify every JSON load path handles missing or malformed data gracefully.
Add a simple pause key (P or Esc).
Add a "Restart Level" option after Game Over.
Clean up leftover code from the pre-JSON version (I noticed a few remnants during the recent changes).
Review collision boxes for trees, bridges, enemies, and castles.

This is the kind of work that makes later development smoother.

Tier 2 — Multiple levels (my favorite new feature)

Right now you have:

Level1.json

I'd move to:

Level1.json
Level2.json
Level3.json
...

Then, when the player reaches the castle:

Level Complete!

Loading Level 2...

instead of

MISSION COMPLETE

The editor already produces compatible files, so this is surprisingly close.

You don't need 20 levels immediately. Even having three would make it feel much more like a complete NES game.

Tier 3 — Mission system

Right now the objective is always:

DELIVER TREATY

Eventually the JSON could include something like:

"mission":"Deliver Treaty"

or

"goal":"Deliver Royal Message"

Then the HUD displays the mission from the level data.

Later you could even add:

Rescue the Princess
Deliver Medicine
Carry Secret Plans

without changing the code.

Tier 4 — Better enemy behavior

Your current AI is actually appropriate for an NES game, so I wouldn't make it dramatically smarter. But a few refinements could add variety:

Wolves patrol vertically or horizontally based on a property.
Bandits have configurable patrol areas.
Wolves could pause briefly when they hit a tree before reversing.
Different enemy speeds.

These would all fit naturally into the JSON format.

Tier 5 — Polish

These are the little touches that make the game feel finished:

Walking animation (2-frame animation would be very NES-like).
Sound effects.
Background music.
A death animation.
A short "Level Complete" fanfare.
Fade in/fade out between screens.
One feature I'd postpone

One thing I would not rush into is adding weapons or combat.

The identity of King's Messenger, as we've designed it, is that you're a courier trying to navigate danger rather than defeat it. That makes it stand out from games like The Legend of Zelda. I'd preserve that identity unless you later decide the game should evolve in a different direction.

If it were my project...

My roadmap for the next several sessions would look like this:

Fix remaining defects.
Support multiple levels (Level1.json, Level2.json, ...).
Add sound effects.
Add walking animation.
Add mission text from JSON.
Add a few more enemy behaviors.

At that point, I think King's Messenger would feel remarkably complete for an original mid-1980s NES-style game. It would be the kind of project that someone could play from start to finish in 20–30 minutes and immediately recognize as an authentic retro experience.
